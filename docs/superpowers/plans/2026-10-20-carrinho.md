# Carrinho da loja — plano de implementação

> **Para quem executa:** use `superpowers:executing-plans` (ou `subagent-driven-development`). Os passos usam caixas `- [ ]`.

**Objetivo:** o cliente monta um carrinho com vários produtos (tamanho e cor), vê subtotal confiável e finaliza pelo WhatsApp do cliente com o pedido já escrito.

**Arquitetura:** o navegador guarda só `productId`, `variantId` e `quantity` (nunca preço) em `localStorage`, lido por um *external store* (`useSyncExternalStore`). A página `/carrinho` pede ao servidor, por uma Server Action pública de leitura, o carrinho **precificado**: nome, foto, preço, estoque e disponibilidade vêm do banco; item removido, despublicado ou esgotado sai do subtotal. Regras de carrinho e de preço são funções puras testadas. Cupom e frete (Melhor Envio) são os próximos planos e entram sobre `priceCart`.

**Stack:** Next.js 16 (App Router), React 19, TypeScript, Zod, Vitest + Testing Library, `lucide-react` (já instalado). **Sem dependência nova. Sem migration.**

**Spec:** `docs/superpowers/specs/2026-10-17-loja-mentoria-area-cliente-design.md` (seção 3 e "Carrinho": *no navegador, sem login, totais no servidor, o servidor nunca confia no preço enviado pelo navegador*). Plano anterior: `2026-10-18-loja-catalogo.md`.

## Restrições globais

- Valores em **centavos (inteiros)**; exibir com `formatBRL` (`@/lib/money`).
- O servidor **nunca** usa preço vindo do navegador; o carrinho guardado não contém preço.
- Páginas continuam Server Components; `"use client"` só no menor componente necessário.
- Interface em **pt-BR**; nada de preço, estoque ou prazo inventado.
- Produto/variação visível = `isStoreProductVisible` (produto e categoria publicados) + variação `published`.
- Trabalhar na `main`; commits locais; **sem push nem deploy** sem aprovação.
- Erros esperados voltam como valor `{ ok, ... }` (Next esconde mensagem de erro lançado em Server Action em produção).
- Textos novos marcados **[copy]** passam por revisão do `copy-editor-ptbr` ao final.

## Foco de revisão (entradas que o spec não menciona e que mordem)

1. `localStorage` bloqueado, vazio, JSON quebrado ou com itens malformados: carrinho vazio, nunca erro na tela. (Tasks 1 e 4)
2. Variação despublicada, produto apagado ou esgotado depois de entrar no carrinho: aparece como indisponível, **fora do subtotal** e fora da mensagem do WhatsApp. (Task 2)
3. Estoque caiu abaixo da quantidade: quantidade reduzida ao estoque, com aviso. (Task 2)
4. Carrinho grande: a mensagem do WhatsApp não estoura o limite de tamanho do link. (Task 3)
5. Duas abas abertas: adicionar numa atualiza o contador da outra. (Task 4)

  export interface PricedCart { lines: PricedLine[]; unavailable: UnavailableLine[]; subtotalCents: number; itemCount: number }
