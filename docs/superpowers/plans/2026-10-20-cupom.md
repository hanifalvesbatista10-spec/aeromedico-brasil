# Cupom de desconto — plano de implementação

> **Para quem executa:** use `superpowers:executing-plans` (ou `subagent-driven-development`). Os passos usam caixas `- [ ]`.

**Objetivo:** o dono cria cupons no painel (percentual ou valor fixo, validade, pedido mínimo, limite de usos) e o cliente aplica o código no carrinho, vendo o desconto e o total na hora.

**Arquitetura:** tabela `store_coupons` com RLS **só para administrador**; o visitante nunca lista cupons: a validação passa por uma função SQL `find_store_coupon(code)` (`security definer`) que devolve **um** cupom ativo pelo código exato. As regras (validade, mínimo, limite, cálculo do desconto) ficam em funções puras testadas, usadas no servidor (`priceCartAction`) e no navegador (resposta imediata ao mexer na quantidade). O desconto nunca ultrapassa o subtotal.

**Tech Stack:** Next.js 16, React 19, TypeScript, Zod, Supabase (migration manual), Vitest + Testing Library. **Sem dependência nova.**

**Spec:** `docs/superpowers/specs/2026-10-17-loja-mentoria-area-cliente-design.md` ("Cupom: percentual ou valor fixo, validade, pedido mínimo e limite de usos"; painel com autonomia total sobre cupons). Plano anterior: `2026-10-20-carrinho.md`. O frete (Melhor Envio) é o plano seguinte e usa estes totais.

## Restrições globais

- Valores em **centavos (inteiros)**; exibir com `formatBRL`; o dono digita em reais (`parseBRLToCents`).
- **Migration entregue como arquivo; quem executa é o responsável** (SQL Editor do Supabase do CMS). O SQL completo vai também no chat.
- Sem `service_role`; autorização = RLS + `is_admin()`. Função `security definer` com `set search_path = ''` e `revoke ... from public`.
- O preço e o desconto **nunca** vêm do navegador como verdade: o servidor recalcula.
- Erros esperados voltam como valor `{ ok, ... }`.
- Interface em pt-BR; textos novos marcados **[copy]** passam pelo `copy-editor-ptbr`.
- Trabalhar na `main`; commits locais; **sem push** sem aprovação.
- O contador de usos (`uses_count`) só passa a subir quando existirem pedidos (plano de pagamento/pedidos). Até lá, o limite de usos vale para cupons já usados fora do site (o dono pode ajustar o contador no painel).

## Foco de revisão

1. Cliente testa códigos ao acaso: só descobre cupom pelo código exato; inativo e inexistente dão a mesma resposta "Cupom não encontrado." (Tasks 1 e 5)
2. Código digitado com minúsculas, espaços ou acento errado: normalizado (`trim` + maiúsculas) antes de procurar. (Tasks 1 e 5)
3. Desconto fixo maior que o subtotal, percentual de 100% e subtotal zero: desconto limitado ao subtotal, total nunca negativo. (Task 2)
4. Cupom que vale só acima de um mínimo, depois de o cliente tirar itens: some o desconto com a mensagem do mínimo, sem travar o carrinho. (Tasks 2 e 5)
5. Banco sem a tabela de cupons (migration ainda não rodada): o carrinho segue funcionando e o campo de cupom responde "Cupons indisponíveis no momento." (Task 5)

- Produces:
  ```ts
  export function normalizeCouponCode(input: string): string   // trim + maiúsculas + colapsa espaços internos em nada
  export type CouponRejection = "not-started" | "expired" | "exhausted" | "below-minimum";
  export type CouponEvaluation =
    | { ok: true; discountCents: number }
    | { ok: false; reason: CouponRejection; message: string };
  export function evaluateCoupon(coupon: StoreCoupon, subtotalCents: number, now: Date): CouponEvaluation
  export const COUPON_NOT_FOUND_MESSAGE = "Cupom não encontrado.";
  ```
  Mensagens **[copy]**: `not-started` "Este cupom ainda não está valendo." · `expired` "Este cupom expirou." · `exhausted` "Este cupom atingiu o limite de usos." · `below-minimum` `Este cupom vale para pedidos a partir de ${formatBRL(min)}.`
  Regras: `startsAt > now` → not-started; `expiresAt <= now` → expired; `maxUses !== null && usesCount >= maxUses` → exhausted; `subtotal < minOrderCents` → below-minimum (checadas nessa ordem). Desconto: percentual = `floor(subtotal × value / 100)`; fixo = `min(value, subtotal)`; sempre `0 <= desconto <= subtotal`. `active` não entra aqui (cupom inativo nem chega pelo `findActiveByCode`).
